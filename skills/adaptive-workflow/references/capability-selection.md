# Choose among installed skills

Read when a plausible installed skill has uncertain fit, unavailable prerequisites, overlapping responsibilities or costly follow-on work. Candidate retrieval supplies options; the host makes the semantic choice.

## Identify the contribution

State the concrete need and constraint in context, without creating a mandatory report. For example, reproducing an intermittent state failure needs controlled execution and relevant observations; a broad style audit does not supply that contribution. A request to explain the installed catalog needs descriptions, not a software development workflow.

Use the current session's catalog before scanning disk. Read a plausible candidate's instructions and relevant resources before adoption. A broad trigger, matching keyword or estimated body length does not establish value. Inspect required outputs and downstream dependencies as well as the entry description; a short entry may initiate substantial work.

## Respect identity and availability

| Observation | Consequence |
| --- | --- |
| The host exposes the candidate with applicable invocation permissions | Assess its actual contribution and prerequisites |
| Two entries share a name | Keep their source paths or IDs distinct; do not guess which instructions apply |
| A skill is present only on disk or in a fresh CLI catalog | Inspect it if useful, but do not claim it is registered in the running session |
| A skill is disabled or restricted to explicit invocation | Preserve the restriction; an inferred match is not an explicit user request |
| A plugin cache entry has unverified enablement | Do not treat cached files as an active capability |
| Instructions or invocation metadata changed after retrieval | Refresh the affected inspection before relying on the old judgment |

If the catalog is incomplete, use available local inventory tools for the relevant capability. A lexical miss is not proof of absence: check plausible descriptions or try an equivalent short local query in their language. Do not read the entire library or repeatedly rescan unchanged files. No helper or additional runtime is required to apply this guidance.

## Decide how to use a candidate

| Finding | Decision |
| --- | --- |
| It supplies the missing contribution and its prerequisites fit | Adopt it and explain what it will do |
| Several candidates supply the same contribution | Prefer the one fitting the project's tools and constraints with less unrelated required work |
| Candidates supply different necessary contributions | Assign each its specific role and reuse the earlier output |
| A required tool, access or project setup is unavailable | Explain the concrete limitation; use a viable existing approach without silently changing setup |
| A useful technique is separable from an unsuitable full workflow | Borrow the technique where permitted and describe partial use honestly |
| Its required scope conflicts with the task or higher-priority instructions | Decline the full workflow and explain the material conflict |
| Existing reasoning, tools or completed work already supply the contribution | Continue directly; no additional skill is needed |

Respect an explicit user selection. Explain a blocker rather than silently switching away from that choice. Skill selection does not grant permission to install software, delegate tasks, publish changes or run commands with additional authority.

## Avoid duplicate and recursive workflows

Check a necessary downstream skill when its contribution is relevant. Do not restart selection because a candidate points back to this manager. Reuse already read instructions while they remain current and preserve completed work across skill transitions. Do not create a plan, checkpoint or extra review merely because another candidate offers one.

For an important choice, distinguish what was considered, what was read and what was actually used. State the useful contribution and material limitations in natural conversation, not a mandatory selection report. Revisit the decision only when task needs, availability or outcomes change.

## Boundary for external capabilities

The default outcome concerns installed skills, including choosing none. No local match does not initiate external search. The retained remote-search and source-collection helpers are optional utilities for an explicit request to find or assess additional skills; they are not prerequisites or fallback stages of local selection. Do not install, initialize or alter third-party skills to make a candidate fit.
