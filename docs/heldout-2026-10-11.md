# Frozen-version forward comparison on new tasks

[中文报告](heldout-2026-10-11.zh-CN.md)

Twelve fresh CLI sessions repaired two actual source defects not used to design the frozen Adaptive Workflow. **All three configurations passed all four task runs. Neither the preregistered quality signal nor a repeated cost signal was reached.** This does not establish that the Skill improves default Codex.

## Provenance and acceptance

The teaching-asset Markdown projection module came from the existing local LessonPilot source: incorrect fence recognition could rewrite a code-sample image, and replacing a destination could change its alt label. The other task used [Mingjian](https://github.com/sky-k111/ai-name)'s existing naming service, based on source commit `39b8e3912cddd6d462d2efb1c46d96dc24a3ac1d`: wrong response shapes leaked exceptions and valid Chinese punctuation was changed before parsing. No implementation defect was injected. These were focused source copies, not whole applications or live production incidents.

Before subjects ran, the evaluator author wrote detailed repair contracts, external checks and separate feasibility references. The Markdown contract covered the existing inline-image grammar, destination-only replacement, resolver calls, preserved line endings and top-level fence recognition informed by [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/#fenced-code-blocks). It excluded full Markdown parsing and nested containers. The naming contract covered five service operations, object extraction and ambiguity, required shapes, duplicate keys and numeric validity, exact decoded strings, valid optional fields, result wrappers, API-key forwarding and provider errors. Tests used fake chat clients; there were no live API calls, database or route integration.

Original Markdown tests passed 11/11 while external checks passed 7/19. No existing Python test suite was discovered for naming; eight visible compatibility checks were authored for this evaluation and passed, while external checks passed 8/55. Separate calibration repairs passed 19/19 and 55/55 plus every visible check. Evaluators were frozen before model execution and were never added to or changed during these cells.

## Registered comparison

The measured Skill was frozen from `d3413226187fd9944c5eec31e95a5f09bb6024e2`. Two tasks × two repetitions × three arms produced exactly twelve sessions:

- Bare: common bundled system skills; no optional process library.
- Library: thirteen unchanged process skills with normal selection, without a forced planning prefix.
- Adaptive: the identical library plus explicitly invoked Adaptive Workflow.

All used gpt-6.1-sol / high, CLI 0.162.0, independent CLI homes and Git roots, neutral instructions and a 720-second cap. All twelve copies and hash checks were completed before any baseline test ran; initial indexes had no derived caches. Shared installed dependencies and server caching remained uncontrolled. Registration preceded subjects; there was no Skill tuning, changed task, added acceptance, replacement run or retry.

Acceptance required frozen external checks, module regressions, original assertions, unchanged contracts and unrelated source, and context/boundary audits. The primary material-quality signal required four accepted Adaptive runs and at most one accepted run in each comparator; this small-sample threshold would still not establish statistical or general superiority. A repeated cost signal required jointly accepted pairs and at least 30% lower uncached input in both repetitions of one task relative to a named control. Neither criterion was reached.

## Interpretation and operational limitations

These are researcher-selected, explicitly specified module repairs. Their defects were real and did not inform this Skill version, but the same author selected tasks and defined contracts/evaluators. They are not fully blind trials, random production sampling, or end-to-end complex-project evaluation. Two repetitions per task do not establish reliability across tasks, and explicit invocation does not demonstrate automatic selection in a running desktop conversation. Cache behavior and concurrent elapsed times were not controlled, so cost causality and speed claims are unsupported. Shared dependencies also prevent claiming a completely cache-free environment; the verified guarantee concerns identical source copies and clean initial Git indexes.

The CLI added project-trust bookkeeping entries without changing registered execution settings. Its observed configuration was retained after each completed run. The live line reader fragmented tool output containing Unicode line separators; audit reconstructed command/status records from those fragments. The intact native session records remain available locally, and reconstructed output text must not be represented as byte-exact native tool output. Neither runner, prompts, Skill nor frozen evaluators changed. No post-hoc cases were added or promoted to independent quality evidence.

The measured results do not justify accumulating generic instructions under a universal improvement claim. Retain experimental positioning. A future redesign should offer concrete project knowledge, executable evidence-state checks or operational constraints that the default host lacks, define a falsifiable benefit before implementation, and evaluate it separately. Those are unvalidated design proposals, not new proven benefits.

Raw prompts, source hashes, frozen assets, native sessions, evaluators, audits and reviewable repair patches remain local. Original projects were not overwritten, and private configuration or third-party copies are not distributed. The [archive trial](real-project-2026-10-11.md) and [synthetic trial](benchmark-2026-10-11.md), including their limitations and negative outcomes, remain published.
