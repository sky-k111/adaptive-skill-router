# 从安装到完整任务：一次使用交付记录

[English](usage-walkthrough-2026-10-15.md) · [安装与跨项目配置](setup.zh-CN.md)

本记录展示公开安装、全局约定、首次选择、实际修复和独立验收的完整过程。没有设置默认 Codex 对照，也不以节省 Token 或普遍质量优势为结论。

## 环境与来源

- 使用公开仓库提交 [e29e8a4](https://github.com/sky-k111/adaptive-skill-router/tree/e29e8a4d71230c7a6b32eb347af199d1283397e0)，由内置安装器从 GitHub 下载独立 Skill；10 个资源与该版本一致。
- 宿主为 Windows、Codex CLI 0.162.0、Node.js 24.18.0，使用用户原有的 gpt-6.1-sol / high 配置。
- 新建独立配置目录和项目副本，没有继承作者的个人指引或此前的对话。把公开的[全局片段](../examples/global-guidance.md)合并进一份简短的工作约定，保留原有内容。
- 为这次任务复制了已有的调试、测试驱动和完成前验证 Skill；Codex 同时提供内置 Skill。这是本次环境准备，不代表本项目附带或要求固定的专业技能库。
- 命令在 workspace-write 沙箱下运行，未关闭沙箱。临时登录文件受单独权限保护，结束后已移除。原始会话、测试副本和环境配置没有随项目发布。

## 任务与首次回答

任务来自仓库原有源码缺陷：运行时只列出父级入口，入口文件删除后，原生适配器递归扫描其目录，可能将从未被运行时列出的嵌套 Skill 当作可用条目。这不是向源码注入的故障，也没有声称它是已知生产事故；复现使用受控运行时响应。

首轮任务没有点名 Adaptive Workflow，也没有指定应选哪些 Skill。它要求保留接口、调用限制和版本检查，只说明着手方式，暂不读取项目代码；允许只读已有 Skill 指引。

实际回答原文节选：

> 本轮仅阅读了 Skill 指引，未读取项目代码、运行检查或修改文件。
>
> 已使用 **adaptive-workflow** 确定方法，并按 **systematic-debugging** 的原则规划排查：先复现、追踪根因，再考虑修复。测试驱动与完成前验证留待实施阶段读取和采用。

工具记录确认这两份 Skill 正文均成功读取。首轮没有项目源码读取、测试或修改；说明中的后续步骤是计划，不是已完成工作。

## 同一会话继续实际工作

随后授权在副本中修复问题，禁止安装依赖、联网、调用其他 Agent、发布和修改用户全局配置。

| 阶段 | 实际行为 |
| --- | --- |
| 选择 | 读取管理和调试指引，说明先定位原因，后续方法按阶段采用 |
| 调查 | 追踪运行时列表到目录扫描的数据流，确认入口缺失时会继续扫描子目录，且结果没有按运行时记录排除 |
| 回归 | 实施阶段读取测试驱动指引；新检查先复现预期失败，修复后 5 项新增检查通过 |
| 修复 | 只修改 [原生发现](../src/native.ts) 和 [相关测试](../test/native.test.mjs)，限制目录扫描深度并排除未列出的文件路径 |
| 验证与收尾 | 读取完成前验证指引，区分通过、失败和受限检查；没有额外增加规划、框架或功能 |

新增检查还覆盖扫描预算、运行时明确列出的合法嵌套条目、禁用与仅显式调用限制，以及正文/调用元数据变化后的重新检查要求。

## 验证结果与保留的失败

最初三次尝试都因验收工具创建的私有目录访问问题，未能完成任务。其中第一次继续会话还使用了该 CLI 不支持的参数。Agent 对读取失败作了如实说明，没有宣称已经使用 Skill 或修复成功。相关记录保留，未计为成功。

成功的两阶段会话改用正常继承访问权限的副本目录；仅为测试 Skill 资源设置必要访问范围，登录文件单独保护，没有开放整个配置目录。

成功会话内仍遇到 Node 测试进程的 `spawn EPERM`：
- Agent 用同一测试框架的单进程方式确认新增回归，并通过 37 项相关检查及 10 项策略检查。
- 它执行的完整检查未通过，不能记为通过。另一次测试临时目录位于 Git 项目内，不满足现有“无 Git 祖先”用例的前提；该失败也保留。
- 独立验收随后在允许启动测试进程、临时目录位于仓库外的环境运行原版完整检查：**157 项通过、2 项文件链接权限受限跳过，策略检查 10/10**，没有删除失败测试来获得通过。
- 预先准备、未交给执行会话的协议检查，在原源码上观察到未列出的条目，修复后为空；同时检查调用限制和正常条目，三个检查组均通过。该检查使用本地子进程模拟协议，不是线上 Codex 运行时兼容性证明。

经审查的修复已纳入本仓库。原始材料和临时配置留在本地；公开的是可阅读的过程与结果，不包含个人路径、登录信息或第三方 Skill 正文。

## 这份记录支持什么

它支持“公开安装与全局约定可以在这套新 CLI 环境中使用，并完成一次实际源码维护任务”的结论。管理 Skill 的作用体现在选择说明、阶段性采用和对受限验证的区分。

它不证明描述匹配单独就能稳定触发，也不证明所有技能库、操作系统或当前桌面会话都表现相同。一次案例不能证明普遍的效果或因果优势。对外介绍时应保留“早期试用”和上述边界。
